# rtl_proto Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stream an RTL-SDR over a local network through a gRPC protocol with adaptive requantization, with a proxy that serves plain rtl_tcp to unmodified clients.

**Architecture:** `rtl_remote` (on the dongle host) implements a gRPC `Receiver` service over `github.com/dim13/r82xx`; samples are read from USB in 16 KiB frames, requantized per frame to 1–8 bits chosen by a queue-occupancy controller, and sent zstd-compressed. `rtl_proxy` (on the client host) calls the service and serves rtl_tcp on localhost, translating commands to `Configure` and decoding frames back to u8 I/Q. Service logic lives in importable packages (`remote`, `proxy`, `codec`) testable without hardware over `bufconn`; the `cmd/` mains only wire USB, flags and gRPC options.

**Tech Stack:** Go 1.27.4, `google.golang.org/grpc`, `google.golang.org/protobuf`, `github.com/klauspost/compress/zstd`, `github.com/dim13/r82xx` (≥ `2ba683d`, has `Chip()`/`BlogV4()`), `github.com/google/gousb`, protoc + protoc-gen-go + protoc-gen-go-grpc.

**Spec:** `docs/superpowers/specs/2026-11-22-rtl-proto-design.md`

## Global Constraints

- Module `github.com/dim13/rtl_proto`, `go 1.27.4`. stdlib `flag` and `log/slog`; no `internal/`, no Makefile, no testify.
- Proto package `rtlproto.v1`, `go_package = "github.com/dim13/rtl_proto/rtlprotov1"`; generated code committed.
- Plaintext gRPC only (`insecure.NewCredentials()`). rtl_remote default listen `127.0.0.1:7373`; rtl_proxy default listen `127.0.0.1:1234`.
- Frame = 8192 complex samples = 16384 raw bytes. u8 zero level 127.5.
- 8-bit frames are bit-exact. Bits per component range 1..8; `StreamRequest` 0 means default: `min_bits` 2, `max_bits` 8.
- Queue between USB reader and sender holds 4 frames, drops oldest when full.
- Controller: step down one bit when more than one frame waits; step up one bit after the queue has stayed empty for 2 s.
- gRPC flow-control windows pinned to 64 KiB on both sides (disables BDP probing); TCP send buffer 64 KiB on rtl_remote.
- Latency target: under 100 ms added between USB read and client write on the local network.
- rtl_tcp greeting: `RTL0`, uint32 BE tuner type (R820T 5, R828D 6), uint32 BE gain count (29). Commands are 5 bytes, no replies; unknown commands consumed and logged, connection stays open.
- Commit messages: short subject line, no AI attribution trailer. Never `git push` without explicit permission.

## Review Focus

1. Retune while streaming: frames keep flowing, `settings_gen` increases on frames after the change. Test in Task 5.
2. rtl_tcp client disconnects mid-stream: proxy cancels `Stream`, remote closes the USB sample reader. Test in Task 6.
3. Remote stream fails (USB error, remote restart): proxy reconnects, re-applies the last settings it sent, resumes writing to the still-connected client. Test in Task 7.
4. Device rejects a setting (e.g. bad sample rate) while streaming: `Configure` returns an error, the stream continues. Test in Task 5.
5. Unknown or garbage rtl_tcp command bytes: consumed, ignored, later valid commands still applied. Test in Task 6.

Behavior to implement (from the spec):
- `Info`: tuner from `Chip()` (R820T → `TUNER_TYPE_R820T`, R828D → `TUNER_TYPE_R828D`, else UNKNOWN), `blog_v4`, `gains_tenth_db` = `tuner.GainSteps`, manufacturer/product from `Strings()`, `current` = full tracked state.
- `Configure`: apply set fields in this order: `ppm`, `sample_rate_hz` (then `SetBandwidth(0, rate)`, as rtl_tcp does), `frequency_hz`, `gain_manual`, `gain_tenth_db` (implies manual), `agc`, `bias_tee`, `direct_sampling`. Validation before touching hardware: gain not in `GainSteps` → `InvalidArgument`; `direct_sampling` ≠ OFF and not `BlogV4()` → `Unimplemented`; on V4 it is accepted and recorded with no hardware action. Device errors → `Internal` with the error text. Stop at the first error; fields applied before it stay applied. A change to frequency, sample rate, ppm or direct sampling increments `settings_gen`. Reply: full tracked state with every field set, `sample_rate_exact_hz` from `SetSampleRate`.
- `Stream`: validate bits (0 → default; outside 1..8 or min > max → `InvalidArgument`). A new `Stream` cancels the active one, which returns `status.Error(codes.Aborted, "superseded")`. Open `dev.Samples()`; a reader goroutine fills `FrameBytes` frames with `io.ReadFull`, stamps `captured` and `first` (complex-sample index from stream start, counting dropped frames), `put`s them; the send loop `get`s a frame, `bits := ctrl.update(q.len(), now)`, encodes, sends `Frame` with `count = FrameBytes/2`, current `settings_gen`, `captured_unix_nano`. On exit (client gone, superseded, error) close the sample reader and wait for the reader goroutine. Sample reader error → `Internal`.

### Task 6: rtl_tcp proxy session

**Files:**
- Create: `proxy/proxy.go`, `proxy/proxy_test.go`

**Interfaces:**
- Consumes: `rtlprotov1.ReceiverClient`, `codec.Decode`, `grpczstd.Name`; tests use `remote.New` + `fake.Device` over bufconn.
- Produces:
  - `type Options struct { MinBits, MaxBits uint32; Backoff time.Duration }` (`Backoff` 0 → 500 ms).
  - `type Proxy struct{...}`; `func New(c rtlprotov1.ReceiverClient, opts Options) *Proxy`.
  - `func (p *Proxy) Serve(ctx context.Context, conn net.Conn) error` — handles one rtl_tcp client until it disconnects or `ctx` ends; closes `conn`; returns nil on normal client disconnect.

Behavior:
- Calls `Info`; writes greeting `RTL0` + BE uint32 tuner enum value + BE uint32 `len(gains_tenth_db)`.
- Opens `Stream` with `MinBits/MaxBits` and `grpc.UseCompressor(grpczstd.Name)`; for each frame, `codec.Decode` into a reused buffer of `count*2` bytes and writes it to `conn` immediately.
- Reads 5-byte commands and maps them: 0x01 `frequency_hz`, 0x02 `sample_rate_hz`, 0x03 `gain_manual = arg != 0`, 0x04 `gain_tenth_db = int32(arg)`, 0x05 `ppm = int32(arg)`, 0x08 `agc`, 0x09 `direct_sampling`, 0x0d gain by index from `gains_tenth_db` (out of range → log, ignore), 0x0e `bias_tee`; 0x07 and 0x0a with arg 0 → ignore silently, otherwise and all other bytes → `slog.Warn` and ignore. Each mapped command → `Configure` with that one field; errors → `slog.Warn`. Successful settings are merged into the proxy's last-settings message (`proto.Merge`) for Task 7. Command names and the `-d` debug log line follow `../rtl_tcp/main.go`.
- Tracks expected next `first_sample`; logs gaps once per second (`slog.Warn("samples dropped", ...)`) and, at debug level, once per second the current bits and latency `time.Since(captured)`.
- Client disconnect cancels the `Stream` context.
